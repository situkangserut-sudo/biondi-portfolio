Design System Foundations

VIDA Digital Identity — Web SDK & platform design system

Status: This case study is still being written. The scope and role notes below are accurate; token tables, documentation screenshots, and adoption notes still need to be pulled together.

Context

VIDA's products span 5 streams built by different teams. Without a shared design system, each stream risked drifting visually and structurally from the others. I built the foundational design system — color, typography, and spacing tokens — along with the Web SDK, which became the single source of truth engineers reference when building verification flows.

Problem

Two separate but related problems: first, there was no documented, WCAG-compliant foundation for color and type that engineering could build against with confidence. Second, the Web SDK's screens had grown without a single reusable structure, making it harder for engineers to know which existing screen type to reuse versus build new.

My role

  • Defined color, typography, and spacing tokens with WCAG compliance as a baseline requirement, not an afterthought.
  • Documented the system in HTML so engineering had a living reference rather than a static file that would go stale.
  • Built and maintain the Web SDK as the SSOT: 59+ screens spanning 5 verification flows, 5 prototypes, and 12 reusable screen types.
  • Applied VIDA's updated brand identity across product flows during a platform-wide redesign, working with the PM to align experience goals with business requirements.

Why 12 reusable screen types mattered

Rather than designing each new verification flow from scratch, engineers and designers could compose new flows from a known set of 12 screen types. This made new flows faster to build and kept the verification experience consistent across streams — a user moving from one VIDA product to another wasn't relearning a new visual language each time.
